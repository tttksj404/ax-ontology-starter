# AX 업무 전환 스타터팩 실행 계획

요청: 어떤 업무든 전체 흐름을 진단하고, Palantir의 객체·관계·행위 모델을 참고한 온톨로지와 근거 검색을 거쳐 보안을 유지하며 AX할 수 있는 재사용 패키지를 만든다. 기존 서버 인프라는 있다고 가정한다. Codex와 Opus 5.5 / max가 설계와 검증에 참여한다.

첫 범위는 특정 업종에 종속되지 않는 로컬 API·CLI 참조 구현과 도입 문서다. 실제 사내 데이터, 외부 시스템 변경, 배포는 연결하지 않는다. 구매·고객지원·입사서류의 합성 팩으로 같은 코어의 전체 흐름을 검증한다.

| 단계 | 통과 증거 | 상태 |
|---|---|---|
| 현재 환경·공식 온톨로지 문서 확인 | Claude CLI·인증 상태, 공식 문서 링크 | 확인 |
| Opus 5.5 max 공동 설계 | 모델 사용 메타데이터와 설계 원문 | 완료 |
| 업무 진단·온톨로지·보안 계약 | 형식화된 입력·스키마·위협 모델 | 완료 |
| 실행 가능한 수직 흐름 | 진단 → 검색 → 제안 → 독립 승인 → 실행 → 감사 | 세 팩 완료 |
| 자동 검증 | 98개 테스트, 타입·린트·HTTP/CLI·독립 패키지 | 완료 |
| Opus 독립 감사·수정·재검증 | 초기 NEEDS_FIX 재현·수정 → 재감사 PASS → 최종 델타 PASS | 완료 |
| 전달·학습 자료 | 실행법, 구조도, 실제 측정·한계, 업종 강화 경로, 공개 파일 ZIP manifest | 완료 |

완료 판단은 실제 구현 범위에 한정한다. 합성 데이터 성공을 실제 기업 성과나 보안 인증으로 표현하지 않는다. 모델 가용성은 호출 결과로 확인하고, 요청 모델이 불가하면 조용히 대체하지 않는다.
