# v0.2 개선 계획

기준일: 2026-10-02. 이전 v0.1 배포물과 감사 기록은 보존한다.

## 목표와 경계

범용 AX 도입을 회사별 업무·배치·데이터 계약에 연결하고, 문서 변경·권한 회수·삭제가 실제 검색과 승인 실행에 반영되는 동작을 구현한다. 로컬 합성 데모와 실제 조직의 준비 상태를 분리한다. 실제 회사의 IdP·ERP·클라우드 계약·계정이 제공되지 않은 연결은 검증됐다고 표시하지 않는다.

## 구현 순서

1. 현재 소스·환경·기존 테스트의 기준 상태를 확인한다.
2. Opus 5.5 max에 설계 초안과 현재 신뢰 경계를 전달해 독립 검토를 받는다.
3. 회사별 도입 진단, 데이터 계약, 출시 평가 기준을 구현한다.
4. 서버 등록 신원에 연결하는 JWT 접근토큰 검증을 추가한다.
5. 계약 기반 문서 갱신·폐기·권한 변경과 감사·재시도·재시작 동작을 구현한다.
6. API·CLI·실행 예제에 기능을 연결하고 보안·운영·분야 확장·학습 문서를 갱신한다.
7. 관련 회귀·타입·린트·실제 HTTP/CLI·패키지 설치 검증을 실행한다.
8. 최종 소스 해시와 증거를 고정하고 Opus 독립 감사의 발견 사항을 수정·재검증한다.
9. v0.2 배포 ZIP과 검증 기록을 새 이름으로 생성한다.

## 완료 조건

- 미확인 보안·데이터·업무 조건은 명시적 보류/차단 이유가 된다.
- 계정·권한 회수 및 JWT 신뢰 조건을 실제 요청에서 검증한다.
- 문서 교체·폐기·ACL 변경 이후 현재 검색과 승인 실행이 오래된 근거를 사용하지 않는다.
- 변경은 원천·계약·리비전·해시·담당자와 연결되고 재전송과 재시작에 안전하다.
- 합성 사례는 실제 기업의 품질·보안·ROI 검증으로 승격되지 않는다.
- 기존 기능 회귀가 없고 새 경계의 실패 사례, API/CLI, 새 wheel과 ZIP을 확인한다.
- 작동 코드, 실제 상호작용 다이어그램, 검증 지표 및 업그레이드 방법을 제공한다.
- Opus 실제 모델/effort와 독립 판정·수정·최종 검증 범위를 증거에 남긴다.

## 역할

Codex가 통합·실행·증거를 담당한다. 독립 Sol xhigh 작업자는 도입 계약, 신원 검증, 지식 수명주기를 파일 단위로 소유한다. Opus 5.5 max는 설계 반례와 최종 감사를 담당한다. 각 작업자는 공유 파일과 이전 증거를 보존한다.

## 배포 시 추가 검증이 필요한 항목

실제 조직의 원천 ACL 동기화, IdP와 키 배포·회전, 모델 계약·지역·보존 조건, 외부 ERP 쓰기 결과 대조, 네트워크 차단, 감사 외부 보존, 백업 복원 및 현업 평가셋은 해당 조직 환경에서 검증한다.

## 실행 체크포인트

- 최초 구현: 통합 286 tests, 정적 검사, 별도 wheel의 실제 CLI/HTTP 실행과 소스 일치를 확인했다.
- 독립 검토: Sol xhigh와 Opus 5.5 max 최초 구현 감사가 로컬 참조 런타임 범위에서 PASS였다.
- 추가 보완: Opus 비차단 권고인 metadata 접근 범위, 중복 snapshot 입력 오류 처리, 필수 증거의 도입 차단 라벨을 모두 구현하고 회귀를 추가했다.
- 재검증: 통합 300 tests, 98개 Python 파일의 정적 검사, 변경 관련 68개 품질 규칙, 설치된 새 wheel의 실제 CLI/HTTP·소스 일치, 합성 업종 세 개를 통과했다. 독립 Sol delta 검토도 지정 범위에서 PASS였다.
- 재감사: 142개 파일을 고정해 공급한 Opus 5.5 max 판정도 PASS였다. 추가로 제안한 기존 문서의 쓰기 ACL 검사·receipt 권한 투영과 계약 변경 후 tombstone을 구현했다.
- 독립 반례 보완: managed 빈 groups 입력으로 활성 문서가 권한 고립되는 P1을 재현하고 upsert/ACL변경에서 422로 차단했다. legacy 빈·불명 ACL의 숨김/404와 통제 migration 경계를 문서화했다. Sol hardening 검토가 표적 45개·핵심 6개 검사와 별도 HTTP/DB probe를 실행하고 지정 범위 PASS를 기록했다.
- 최종 실행: 316 tests, 102개 Python 파일 정적 검사, 변경 관련 72개 품질 규칙, 새 wheel의 실제 HTTP/CLI/restart와 추가 쓰기 ACL·빈 groups·replay·drift 삭제 HTTP, 구매·고객지원·입사서류 합성 데모를 통과했다.
- hardening 감사: runtime 전체와 관련 테스트·문서·실행 증거 119개 파일을 고정한 Opus 5.5 max는 기존 다섯 보완을 확인했지만 회사 간 global document ID의 선점·존재 탐지 P2로 NEEDS_FIX를 판정했다. 실제 응답을 보존하고 managed upsert의 tenant namespace 강제, 같은 tenant의 ID 발급 경계, 계약 제거 전 정리·ACL 확대 권한 문서와 회귀를 보완한다.
- namespace 수정: DB 조회 전 tenant-qualified ID guard, managed 예제·fixture 이관, legacy cleanup과 계약 재등록 회귀를 구현했다. 같은 tenant ID 할당, legacy/bootstrap prefix 충돌, ACL 확대 권한은 회사 운영 조건으로 명시했다.
- 새 통합 검증: 전체 325 tests, 103개 Python 파일 포맷·Ruff·타입, 변경 관련 73개 품질 규칙, 새 wheel의 실제 HTTP namespace 8조합·CLI/restart·ACL/replay/drift cleanup, 세 합성 업종 데모를 통과했다. Sol namespace 검토도 52 tests와 독립 probes에서 지정 범위 PASS였다.
- 최종 감사: current runtime 전체와 표적 테스트·관련 문서·실행 증거 91개 파일을 고정해 실제 Opus 5.5 max에 공급했고, 실제 응답의 PASS와 model·max 호출 인자·원본 해시를 확인했다. 이전 NEEDS_FIX와 수정 이유도 보존했다.
- 증거 보완: 독립 52개 검사에서 실행한 8개 파일의 명령·해시와 학습 가이드·v0.2 예제의 namespace 대조를 별도 기록으로 연결했다. 비차단 회귀 강화 후보는 완료한 기능과 구분해 검증 문서에 남겼다.
- 배포 절차: 새 ZIP의 내부 manifest를 모든 파일 바이트와 대조하고 최종 감사 91개·검사 소스 107개 파일의 해시 결속을 검증한다. 생성 후의 실제 ZIP 해시·파일 수·검증 결과는 ZIP 밖의 `artifacts/ax-ontology-starter-v0.2.0.delivery.json`에 기록해 자기 참조를 피한다.
