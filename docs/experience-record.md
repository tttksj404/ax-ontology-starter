# 경험 기록: AX 스타터팩 (ax-ontology-starter, 팔란티어 AX 학습 계열)

- 계열: palantir-ax-playbook(학습 노트, 이 기록을 가리키는 포인터만 둠), ai-harness-loop-orchestration(별도 색인, 제외)
- 기간: 학습 노트 2026-08-14 ~ , 스타터팩 공개 커밋 2026-10-06(v0.3.0). 실제 개발 시작일 미확인(Claude·Codex 발화 검색, 2026-11-24: 해당 발화 없음)(공개 저장소 이력은 2개 커밋)
- 인원·구성: 커밋 작성자 `tttksj404` 한 계정. AI 모델(독립 검토 "Sol", "Opus 5.5")을 검토자로 활용한 기록이 있음
- 본인 역할: 업무 진단, 온톨로지, 권한 적용 RAG, 검토형 LLM Wiki, 승인 실행 흐름의 설계·구현·검증 문서화. AI 코딩 에이전트 사용 비중은 미확인(Claude·Codex 발화 검색, 2026-11-24: 해당 발화 없음)
- 성격: 개인 프로젝트(로컬 참조 구현). 실사용자·실제 회사 적용 없음
- 최종 갱신: 2026-11-23

## 1. 상황과 판돈
- 무엇 때문에 시작했나: 팔란티어 공개 자료로 기업 AX를 공부한 뒤(palantir-ax-playbook), 업무 객체와 근거를 연결하고 사람이 승인한 작업만 실행하는 구조를 직접 만들어 보려 함.
- 왜 중요했나: 본인 서술(2026-11-06)로는 누구든 AX를 할 수 있게 하려는 공익적 의도. 구체적 수요자·기관은 없음.
- 그때의 제약: 실제 회사 데이터가 없어 구매·고객지원·입사서류 점검 합성 데모만 사용. 회사별 신원·데이터 계약·평가셋은 연결하지 못함(README가 명시).

## 3. 판단
- 정한 것: RAG는 현재 원문과 권한을 확인하는 근거 계층, Wiki는 사람이 검토해 버전 게시하는 파생 계층으로 분리. Wiki가 원문이나 작업 승인 근거로 자동 승격되지 않게 함(V03_RELEASE).
- 정한 것: 쓰기는 SQLite의 로컬 검토 상태 변경 하나로 제한. ERP 발주, 환불, 급여, 채용 결정, 설비 제어 커넥터는 넣지 않음.
- 정한 것: 실행은 제안, 변경 전후 확인, 별도 사람 승인, 실행, 되돌리기, 해시 체인 감사 순.
- 정한 사람: 본인.
- 버린 선택지: Wiki→Wiki 합성, 원천 감시와 자동 재컴파일 큐는 구현하지 않음(README에 없음으로 명시). 그 밖의 대안은 미확인(Claude·Codex 발화 검색, 2026-11-24: 해당 발화 없음).
- 판단 근거: docs/ARCHITECTURE.md, SECURITY_MODEL.md, 감사 증거(docs/evidence). 판단 당시의 논의는 미확인(Claude·Codex 발화 검색, 2026-11-24: 해당 발화 없음).

## 4. 결과와 상대의 변화
- 확인된 결과: v0.3.0 로컬 참조 구현. Python CLI, 인증 API, SQLite 저장소, 3개 합성 업종 데모.
- 수치: 테스트 421개 통과, Ruff ALL·145개 Python 파일 format 통과, basedpyright 오류·경고 0, wheel 설치본의 runtime 70개 모듈 바이트 일치, v0.2 DB를 v0.3로 여는 이전 검사 통과(docs/V03_RELEASE.md, 2026-10-06 revision-3). 측정 조건은 개인 로컬 환경, 합성 데이터.
- 상대의 변화: 해당 없음(외부 사용자 반응 기록 없음).
- 안 된 것·남은 문제: 회사 적용 전 확인할 "알려진 권고 8개"가 남아 있음(내용은 V03_RELEASE.md 참조). 합성 데모 성공은 실제 회사 배포·보안 인증·모델 품질 증명이 아님(README). 이전 394개·417개 결과와 NEEDS_FIX는 이력으로 보존됨.
