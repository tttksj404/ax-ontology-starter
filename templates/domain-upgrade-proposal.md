# 분야팩 업그레이드 검토서

대상 업무 / 팩 ID / 현재 버전 / 제안 버전:
업무 책임자 / 데이터 담당자 / 개발 담당자 / 보안 검토자:

## 바꾸려는 문제

현업에서 실제 관측한 실패와 해당 자료/권한/시점의 재현 조건을 적는다. 정상·실패·예외 사례, 오류 심각도, 기준선을 제시한다. 합성 실험과 실데이터 측정을 구분한다.

## 변경 계약

객체·속성·관계·자료 출처·효력·분류·ACL·규칙·실행 처리기 중 무엇이 바뀌는지 명시한다. 읽기 범위, 외부 전송, 쓰기 권한, 자동화 수준이 늘어나는 변경은 따로 표시한다. 변경하지 않은 업무 경계도 적는다.

## 동결 평가와 검증

평가셋 버전/해시, 현업 정답 검토자, 수정 전/후의 같은 평가 결과, 권한 경계·자료 만료·주입·예외·실패 복구 회귀, 모델/프롬프트/게이트웨이 버전, 지연·비용·사람 검토시간을 적는다. 다른 문항이나 다른 자료로 낸 점수를 단순 전후 개선으로 보고하지 않는다.

## 배포와 되돌리기

팩/DB 마이그레이션, 진행 중 제안의 처리, 백업/복구, 제한 대상·한도, 관측과 중단 조건, 책임자 채택, 독립 감사 결과와 적용 소스 해시를 적는다. 승인자·실행자는 필요한 현재 권한만 가진다.

## 결정

채택 / 수정 후 재검토 / 보류와 그 근거를 남긴다. 모델의 자체 평가나 이전 버전 감사 PASS를 새 버전의 승인으로 재사용하지 않는다. [업그레이드 가이드](../docs/UPGRADE_GUIDE.md)의 L0–L4 중 어느 단계 조건을 충족했는지 명시한다.
